# SCAPS-1D Verification Batches — README

Generated by `generate_scaps_batches.py` for the ITO/PCBM/MAPI/PEDOT:PSS/Au
verification study (Table 3.1 parameter bounds).

## What's in this folder

| File | Contents |
|---|---|
| `batch_01.script` … `batch_10.script` | SCAPS-1D script files (SCAPS 3.0.02 script language). Each runs **1,000** physics-validated device configurations and saves one `.iv` result file per configuration. |
| `batch_01_params.csv` … `batch_10_params.csv` | The exact 15 parameter values (original units: nm, eV, m⁻³) used in each simulation of that batch, keyed by `sim_id`. |
| `all_batches_params.csv` | All 10,000 configurations combined, with a `batch` column. |
| `generate_scaps_batches.py` | The generator itself — rerun it to change the sample size, seed, or `.def` filename. |

10,000 configurations total (1,000 × 10 files), sim IDs `sim00001`–`sim10000`.

## Before you run these in SCAPS

Each script starts with:
```
load definitionfile perovskite_baseline.def
```
**You must create `perovskite_baseline.def` first**, through the normal SCAPS
GUI, with:
- the ITO / PCBM / MAPI / PEDOT:PSS / Au stack (layer1 = PCBM/ETL,
  layer2 = MAPI/absorber, layer3 = PEDOT:PSS/HTL)
- the electrode work functions fixed to the values used in the reference
  ML study
- the AM1.5G spectrum loaded
- the I-V sweep window (start/stop voltage, number of points) set the way
  you want it — the scripts only override the 15 sampled layer parameters
  (thickness, chi, Eg, ND, NA for each of the 3 layers); everything else
  in the `.def` file is left untouched.

Save it into SCAPS's `def\` folder, then either:
- keep the name `perovskite_baseline.def`, or
- rerun the generator with `--defname yourfile.def` to bake in a different name.

## Running a batch

In SCAPS: **Action panel → Load script → Run script**, and point it at
`batch_01.script` (then `batch_02.script`, etc.). Each batch takes a while
(1,000 single-shot IV calculations) — run them one at a time or queue them
overnight.

Each simulation block looks like:
```
set layer1.thickness 0.043219
set layer1.chi 3.8878
set layer1.Eg 2.0839
set layer1.ND 8.4868E+14
set layer1.NA 1.3767E+13
... (layer2, layer3 likewise)
calculate singleshot
save results.iv sim00001.iv
clear simulations
```
`save results.iv` writes the I-V curve **and** the Voc/Jsc/FF/η summary
header for that run to `scaps\results\sim00001.iv` — matching the parsing
step already described in the methodology (Section 3.5): a second Python
script reads each `.iv` file's header for Voc, Jsc, FF, and computes PCE
from the maximum power point.

## Unit conversions applied (Table 3.1 → SCAPS)

| Table 3.1 | SCAPS command | Conversion |
|---|---|---|
| Thickness (nm) | `set layerN.thickness` (μm) | ÷ 1000 |
| Conduction band edge Ec (eV) | `set layerN.chi` (eV) | none — Ec **is** the electron affinity chi |
| Valence band edge Ev (eV) | `set layerN.Eg` (eV) | `Eg = Ev − Ec` (SCAPS has no direct "Ev" input) |
| Donor concentration ND (m⁻³) | `set layerN.ND` (cm⁻³) | ÷ 1e6 |
| Acceptor concentration NA (m⁻³) | `set layerN.NA` (cm⁻³) | ÷ 1e6 |

## Physics validation applied before writing each block

A sampled configuration is only written into a script if **all** hold:
1. Positive band gap in every layer (`Eg = Ev − Ec > 0`).
2. ETL conduction band at/above the absorber conduction band
   (`L1_E_c ≥ L2_E_c`) — lets electrons cascade toward the ETL.
3. HTL valence band at/below the absorber valence band
   (`L3_E_v ≤ L2_E_v`) — lets holes cascade toward the HTL.
4. Absorber thicker than both transport layers.

Rejected combinations are resampled (rejection sampling) until each batch
reaches exactly 1,000 valid configurations. With the current Table 3.1
bounds the reject rate is ~0%, since the ETL/absorber and HTL/absorber
band-edge ranges barely overlap by construction — the check still runs on
every sample and will start rejecting configurations if the bounds are
ever widened.

## Not included: the two "point verification" devices

The methodology also calls for explicitly re-simulating the **exact**
baseline device and the **exact** ML-optimized device (not just the random
sample) for direct comparison. Those two configurations aren't in this
batch — I don't have their specific 15 parameter values (only the
resulting PCE figures, 19.92% and 21.69%, are in the document). Send me
those two parameter sets and I'll add them as two extra one-off scripts.

## Reproducing or resizing this batch set

```bash
python3 generate_scaps_batches.py \
    --n-per-batch 1000 \
    --n-batches 10 \
    --seed 42 \
    --defname perovskite_baseline.def \
    --outdir ./scaps_batches
```
Change `--seed` for a different random draw, or `--n-per-batch` /
`--n-batches` to resize.
